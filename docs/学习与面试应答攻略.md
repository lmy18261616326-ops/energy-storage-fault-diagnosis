# 储能双向 DC/DC 故障诊断项目：学习与面试应答攻略

## 0. 使用方法

这份攻略不是背诵稿，而是一条可以经受追问的知识链：

~~~
物理系统 → 控制目标 → 故障机理 → 可观测信号
         → 数据生成 → 泄漏防护 → 模型评估
         → 失败诊断 → 部署门禁
~~~

每学一个概念，都要能指出对应的模型、代码、测试或结果。推荐顺序是：先跑通测试和演示，再读架构图，再读数据与算法代码，最后练习口述和追问。

## 1. 项目的三种讲法

### 1.1 30 秒版

> 我做了一个基于 MATLAB/Simulink 和 Python 的储能双向 DC/DC 故障诊断项目。仿真侧覆盖充放电控制、传感器偏置、开关开路和高阻故障；算法侧按工况分组，使用冻结后盲测、故障前负对照和外部域偏移审计。我没有只追求高分，而是通过盲测发现开路故障不可观测和跨域失效，再增加器件级观测并设置模型晋级门禁。

### 1.2 90 秒版

> 项目对象是电池与 400 V 直流母线之间的双向 Buck-Boost 变换器。Simulink 侧建立电压外环、电流内环、PWM、模式切换、能量保护以及故障注入；数据侧用 RunID 和 OperatingPointID 组织工况，故障前和不可观测窗口保留用于审计，但不进入训练。机器学习侧不做随机窗口切分，而是按工况分组，并把特征筛选、调参、校准和阈值选择限制在训练折内。早期冻结模型在 216 个新盲测 Run 上只有 43.79% Macro-F1，S1/S2 开路召回率都只有 13.79%。我没有在盲测上继续调参，而是把问题定位到开关故障可观测性，建立 v06 器件电压、电流和 Ron 估计。后续又用故障前负对照发现合成数据的 seed/phase 风险，因此即使指标较高，仍阻止模型晋级。

### 1.3 3 分钟架构版

按五层展开：

1. **物理层**：电池、直流母线、电感、开关器件、母线电容和负载。
2. **控制层**：电压外环生成电流参考，电流内环生成占空比修正，PWM 和互锁驱动功率器件。
3. **安全与故障层**：模式许可、预充、零流切换、故障闭锁，以及传感器偏置、开路和高阻故障。
4. **数据与算法层**：信号对齐、10 ms 窗口/5 ms 步长、物理残差、分组切分、树模型/线性模型/CNN 对比。
5. **审计层**：真值信号禁入模型、冻结后盲测、故障前负对照、外部域偏移和晋级门禁。

## 2. 必须真正掌握的技术

### 2.1 为什么需要双环控制

快速电流内环直接约束电感电流，负责跟踪电流命令和抑制快速扰动；较慢的电压外环根据母线电压偏差产生电流参考。内环必须明显快于外环，否则外环面对的不是近似稳定的“可控电流执行器”，两个环可能相互争夺控制权。

面试时不要只说“双环更稳定”，还应说明：

- 内环对应功率器件和 PWM 的快时标；
- 外环把母线储能偏差转换为充放电功率需求；
- 限幅、参考斜率限制和 anti-windup 是实际系统的必要部分；
- 外环输出不能绕过电池电流、SOC 和安全许可约束。

### 2.2 充放电符号约定

项目把电感电流正方向定义为母线到电池，因此充电为正、放电为负。母线电压高于参考时应要求电池吸收能量；低于参考时应要求电池放电支撑母线。

任何功率残差都必须先声明电压、电流方向。否则看似正确的功率守恒式可能只是符号恰好抵消。signal_config.m 中集中记录了源侧、电池侧和负载侧的功率方向因子。

### 2.3 为什么模式切换不能直接反向

充电到放电不能只把参考从正值改成负值。安全顺序通常是：

1. 电流参考按限定斜率回零；
2. 电流低于零流阈值并保持规定时间；
3. 关闭 gate enable；
4. 执行主开关、预充或源侧连接操作；
5. 复位或重新初始化 PI 状态；
6. 在新方向软启动。

核心原则：不带大电流改变主回路；互补开关不同时导通；故障安全命令优先于正常模式命令。

### 2.4 故障机理、信号和难点

| 故障 | 直接影响 | 可用信号/特征 | 关键难点 |
|---|---|---|---|
| 母线电压传感器偏置 | 控制器看到错误母线电压 | 电压误差、Duty、功率平衡残差 | 负载阶跃也会产生相似瞬态 |
| 电感电流传感器偏置 | 内环看到错误电流 | 电流对残差、跟踪误差、控制输出 | 两个电流传感器不一致不能天然定位故障源 |
| S1 开路 | 应导通区间无法导通 | 门极期望/实际不一致、局部电流畸变 | 只有“本应导通”时才可观测 |
| S2 开路 | 影响另一能量方向或续流路径 | 同上 | 充放电模式改变可观测性 |
| 开关高阻 | 导通压降和损耗上升 | 器件压降/电流、Ron 估计 | 温度、噪声、量化和通道错位影响阈值 |

### 2.5 可观测和可分类不是一回事

可观测性回答“现有测量是否包含足够信息”；可分类性回答“在当前数据分布和特征下，算法能否形成分界”。

如果 S1 在某段时间本来就不应导通，S1 开路在该窗口可能没有任何外部表现。正确做法不是强行给它故障标签，而是保留运行记录、设置 FaultObservableRatio，并令 IsTrainingEligible=0。换更复杂分类器无法创造不存在的信息。

### 2.6 为什么不能随机切窗口

相邻滑窗共享大量原始采样点。同一 Run 的窗口还共享相位、噪声底、初始条件和控制器状态。随机分窗会让高度相关样本同时进入训练和测试，造成“认出同一次仿真”的假高分。

本项目以 OperatingPointID/Run 为分组单元。分组后指标下降不代表验证方法变差，而通常说明原随机切分过于乐观。较低但可信的分数优于高但泄漏的分数。

### 2.7 为什么使用 Macro-F1

Accuracy 容易被健康类或易分类类别主导。Macro-F1 先计算每个类别的 F1，再等权平均，使小类故障的漏检直接反映在总指标中。但仍需同时报告：

- 健康误报率 FAR；
- 高风险故障召回率；
- 逐类 precision、recall、F1 和支持 Run 数；
- Run 级置信区间；
- 误报和漏检在工况上的集中程度。

### 2.8 为什么树模型可能优于 1D-CNN

当前主任务的有效独立样本是 Run，不是滑窗行数；数据呈现“小样本、高维、结构化统计特征”特征。树集成和正则化线性模型有合适的归纳偏置，对阈值和非线性交互也很高效。CNN 需要更多独立原始序列和更严格的对齐/增强。选择简单模型是容量与证据匹配，不是技术落后。

### 2.9 冻结后盲测

盲测前必须冻结：

- 特征列表和排除规则；
- 缺失值与预处理策略；
- 模型与超参数；
- 概率校准方法；
- 决策阈值；
- 代码、配置和模型哈希。

冻结后才生成或解封盲测，并只评估一次。如果看过结果后继续调参，该数据就变成开发集，不能再称盲测。

### 2.10 故障前负对照

故障发生前，不同故障类别的波形理论上不应携带未来标签。若此时仍显著高于随机水平，常见原因包括：

- 不同类别使用不同随机种子区间；
- 种子影响噪声或周期信号相位；
- RunID、文件顺序或时间戳编码标签；
- 预处理在全数据拟合；
- 相关工况跨训练和测试折。

v19 的故障前 Macro-F1 约 0.1511，接近六类随机水平 0.1667，但数据生成器仍存在类别 seed 区间风险，所以项目仍阻止晋级。这体现“统计检查未报警”不等于“生成机制必然无风险”。

### 2.11 外部域偏移

外部实验数据与合成训练数据的电压等级、电流范围、测量位置和通道集合不同。当前外部数据只覆盖冻结模型 950 个特征中的 100 个，且 82.6% 的共享特征单元超出训练范围；外部标签也不对应冻结模型的六类故障。

因此，外部数据可以用于波形完整性、状态可分性和域偏移审计，不能用于声称六类故障外部准确率。把 850 个缺失特征用中位数补齐后得到的概率只能作为压力诊断。

## 5. 高频面试问题与参考回答

### Q1：项目解决了什么问题？

**回答：** 它不只是训练一个分类器，而是建立从功率变换器物理模型、故障可观测性、批量仿真到可审计验证的闭环，重点回答“一个仿真高分模型是否真的利用了故障后物理信息，并能否跨新工况泛化”。

### Q2：你具体做了什么？

**回答结构：** 按模型、数据、算法、验证和工程五层说明个人工作，每层给出一个可核对文件或结果。不要把未亲自验证的原始参考模型说成个人原创。

### Q3：为什么用 Simulink？

**回答：** 故障影响具有动态性和模式依赖，静态表格不能表达门极开关、电感储能和闭环反作用。Simulink 可以联合功率级、控制器和故障注入，并通过 SimulationInput 批量扫描工况。

### Q4：为什么同时有 v05 和 v06？

**回答：** v05 是五类数据集与能量保护的可复现基线；v06 增加器件电压/电流直接观测，服务开关高阻和可观测性专项。两者的证据域不同，不能混报指标。

### Q5：为什么开路故障盲测很差？

**回答：** 开关只有在本应导通的模式和 PWM 相位才可观测；早期特征又主要是系统级电流电压，局部故障容易被闭环补偿或工况变化掩盖。新工况打破相关性后，S1/S2 召回率降到 13.79%。正确改进是增加局部观测和物理判据，而不是只换复杂分类器。

### Q6：盲测 Macro-F1 只有 43.79%，项目失败了吗？

**回答：** 对该版本的部署目标而言没有达标；对研究目标而言，盲测成功发现了开发评估未暴露的结构性问题。我保持盲测一次性，定位到类别和工况，阻止部署，并据此修改可观测性设计。这个过程比在盲测上调参得到虚假高分更有价值。

### Q7：如何证明没有数据泄漏？

**回答：** 不能声称绝对没有，只能列出控制证据：按工况/Run 分组；排除真值和标签派生字段；折内特征处理、调参、校准和阈值；冻结后盲测；故障前负对照；重复键检查；数据生成机制审计。

### Q8：为什么使用嵌套交叉验证？

**回答：** 如果同一批折既用于挑候选又用于报告最终性能，结果会对候选搜索过拟合。外层只评估，内层在外层训练数据中选择模型、校准和阈值，保持外层工况对全部选择过程不可见。

### Q9：为什么固定候选 94.93%，嵌套结果是 90.72%？

**回答：** 固定候选估计某个预先给定模型；嵌套结果包含模型选择本身的不确定性，更接近整条建模流程的泛化表现。后者更保守很正常，不应只报更漂亮的数字。

### Q10：为什么健康 FAR 要单独报告？

**回答：** 工业误报会导致无故停机、保护误动作和报警疲劳。Macro-F1 不能保证健康类风险满足业务要求，因此阈值搜索需要显式约束 FAR，同时保持关键故障召回。

### Q11：为什么不能把 true-measured 当特征？

**回答：** true 信号只存在于仿真，是故障注入校验用的答案。部署时拿不到，把真值残差作为特征等于标签泄漏，所以特征策略明确排除全部真值族。

### Q12：功率平衡残差有什么作用？

**回答：** 它把源、电池、负载和储能变化放在符号明确的守恒关系中。传感器故障会破坏一致性。但残差必须处理采样对齐、开关纹波、方向和储能项，不能简单写成 Pbat-Pbus。

### Q13：为什么高阻可以考虑物理阈值？

**回答：** 在确认器件导通且电流可测时，压降/电流可以估计 Ron，与故障机理直接对应。阈值仍需考虑温度、VCE(sat)、量化和通道错位。当前证据只支持特定仿真条件下约 12 mΩ 以上，不可任意外推。

### Q14：50 µs 采样为什么可能看不到开关细节？

**回答：** 20 kHz PWM 周期正好是 50 µs。同周期固定取样会总落在相同 PWM 相位，产生固定相位混叠。v06 对器件诊断量用 1 µs 采样，再按 PWM 周期聚合。

### Q15：项目为什么有 25 GiB？

**回答：** 空间主要来自多代原始 CSV/MAT、合并数据和实验产物，不是源代码。现在已经把数据、缓存、模型产物、第三方资料和源代码分离，GitHub 只保留轻量源文件，并提供无大数据 demo。完整数据未来应进入对象存储/DVC，而不是 Git。

### Q16：如何保证长时间仿真可恢复？

**回答：** 每个 Run 独立落盘；批次后释放 SimulationOutput；resume 根据 RunID 跳过完成项；失败项单独记录；缓存和并行目录重定向到项目盘；合并时检查重复、缺失和覆盖。

### Q17：为什么外部数据不能直接算准确率？

**回答：** 外部 21 个状态与冻结六类故障标签没有语义重叠；只有两类可假设映射的 V/I 信号，而模型依赖 12 个原始通道和 950 个特征；测量位置也未确认。因此强行补 850 个特征后算准确率没有意义。

### Q18：项目当前最大的技术债是什么？

**回答：** 需要重新生成一套噪声/相位种子与标签解耦的冻结盲测，并把 v06 动态器件观测纳入统一数据口径。第二优先级是 HIL/硬件测量链，验证温度、共模、带宽和实际传感器误差。

### Q19：如果再给两周，你会做什么？

**回答：** 第一周冻结新数据生成器：配对种子、标签独立噪声、配置和文件哈希，并先做小规模故障前负对照。第二周在不看标签结果的前提下生成新盲测，只评估一次，输出 Run 级置信区间和工况诊断。若有条件，并行做最小 HIL 测量链。

### Q20：如何走向部署？

**回答：** 固定可用通道、采样率、滑窗和计算预算；把预处理与模型一起封装；测试最坏时延和内存；使用置信阈值、持续时间和状态机去抖；诊断先输出建议/降额或保护请求，不直接控制高危执行器；按 MIL→SIL→PIL/HIL→台架扩大证据。

## 6. 三个 STAR 故事

### STAR 1：盲测失败后没有在测试集调参

- **Situation**：开发指标较好，但 216 个冻结盲测 Run 的 Macro-F1 只有 43.79%。
- **Task**：判断是数据、模型、阈值还是可观测性问题，同时保持盲测一次性。
- **Action**：锁定模型哈希；输出逐类和工况诊断；发现 S1/S2 召回率均为 13.79%，健康误报集中在两个高负载工况；转向器件可观测性。
- **Result**：阻止不可靠模型部署，建立 v06 器件级测量和 Ron 证据链。

### STAR 2：审计“看上去很好”的模型

- **Situation**：合成参考域固定候选 Macro-F1 达到 94.93%。
- **Task**：判断高分来自故障后物理信息还是生成器捷径。
- **Action**：使用故障前区间做负对照；与随机水平比较；审查 RandomSeed 与周期相位逻辑。
- **Result**：负对照接近随机，但仍发现 seed 设计风险，标记 promotion_blocked=true，要求新冻结盲测。

### STAR 3：把 25 GiB 研究工作区整理成可发布工程

- **Situation**：源代码、缓存、多代数据和第三方资料混合；README 模型版本不一致；审计脚本指向不存在模型。
- **Task**：保留所有原始数据，同时形成轻量、可复现、可解释的 GitHub 版本。
- **Action**：统一 v05/v06 角色；修复审计入口；建立 MATLAB Project、Git 忽略、Python CI、锁定环境和无大数据 demo。
- **Result**：形成可以自动验证的源代码仓库，并将研究指标、限制和晋级状态集中记录。
